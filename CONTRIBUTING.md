# Contributing to Konjugate

Ideas, discussions and contributions are welcome. This page explains the one formal step: the Contributor Copyright Assignment Agreement.

## The CLA

Konjugate is licensed under the Mozilla Public License 2.0, and the copyright in everything published in this repository is held by its owner, Zenin Easa Panthakkalakath. To keep it that way, everyone who contributes signs the [Contributor Copyright Assignment Agreement](CLA.md) (the "CLA"), which assigns the copyright in their contributions to the owner. The CLA also gives you a license back to keep using your own work, and it only covers what you actually own. Please read it; it is short.

## How to sign

1. Open a pull request as usual.
2. A bot checks the pull request and, if anyone on it has not signed, comments with the signing instructions and shows a failing `CLA` check.
3. Post the sentence from that comment, exactly as written, as a comment on your pull request: `I have read the Konjugate CLA v1.0 and I hereby sign it.`
4. The check turns green within a minute. You never need to sign again for future pull requests unless the CLA changes. If the check does not update, comment `recheck`.

No account, email or paperwork beyond your GitHub account is needed, and the check must pass before a pull request can be merged.

## Before you sign

- Only sign if you wrote the contribution yourself and are free to assign it. If your employer, school or a client may own it, get their written permission first, or do not contribute.
- If your contribution includes anything you did not write (code copied from elsewhere, generated material), say so in the pull request and name the source and its license. Material under a license that is incompatible with the Mozilla Public License 2.0 cannot be accepted.
- Every commit on the pull request must be authored with an email address that is linked to your GitHub account, because that account is what signs. Otherwise the check fails and asks you to fix it.

## Records and versions

Signatures are recorded in the `cla-signatures` branch of this repository, in `signatures/cla-v<version>.json`, with your GitHub account, the date, the pull request and a hash of the CLA text you signed. The CLA states its version at the top; if it changes materially, the version is raised and contributors are asked to sign the new one on their next pull request, while earlier signatures stay on record against the version they signed.

## Add-ons

Add-ons and plugins that live in their own repositories are not part of this repository and are not covered by the CLA; their authors choose their own terms.
