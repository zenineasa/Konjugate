                AnalysisCausal inference
                
            
                Results mode · Model lockedClose results to make changes.
                
            
                
                
                Import a CSV of multivariate time-series data -- a numeric, evenly spaced time column, then one column per variable -- and propose candidate directed relationships from it.
                
                
                
                
            
                
            
                
                
                Column mapping
                
                
                Each column is matched to an existing node's state by exact name, or creates a new node.
                
                
                
                
                
                
                
                    
                    
                
                
                
                Fitted equations are calibrated to this CSV's own sampling interval. Results may drift if the project's own time step is set much finer than that.
                
            
                
            
                
                
                Candidate relationships
                
                
                One row per proposed directed edge. Lagged means the source's past value predicts the target; correlation-only means the two are related but no clear direction was found.
                
                
                
                
                
                    
                Self terms
                
                    
                Each target's own recovered persistence/decay rate, applied to the node's own state rather than as a relationship between two nodes.
                
                    
                
                
                
                
                
                    
                Inputs
                
                    
                Check any column that should replay its own recorded values exactly instead of being explained by a fitted equation -- driven by a generated C++ provider, exact at any simulation step size. This replaces whatever candidate edges or self term would otherwise target that column. Most useful for a column nothing else predicts (its only alternative is a self term that settles toward equilibrium rather than reproducing the real fluctuation, or -- if not even that -- staying frozen at its initial value for the entire run), but any column can be replayed this way, for instance to hold it to ground truth while the rest of the model runs on the fitted equations.

                Reading another logger's file
                
                
                Say once how to read it: which column holds the time and how it is written, the time zone it was written in (the clocks changing is taken care of), and for each column you want, whether it is an input or measured, its name as the model calls it, its unit, and how to turn the logger's numbers or words into the model's (a scale and an offset: °C to K is an offset of 273.15; a percentage of a 3 kW heater to watts is a scale of 30). The settings are kept with the project.
